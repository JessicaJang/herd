My personal agent stack. A border collie herds many sheep to one place. herd herds my skills, settings and repo notes to one place.

It is a hub repo, not a monorepo. It does not hold project code. It holds the skills, rules and settings that every agent uses.

Everything in git is general. Job-specific skills, playbooks and notes live in a local `work/` folder that is not in git.

Note: `work/`, `herd.yaml` and `memory.md` are local only. `setup.sh` makes `herd.yaml` and `memory.md` from the `.example` templates. Copy `work/` from your private backup.

## Setup

1. Clone the repo:
   ```bash
   git clone https://github.com/JessicaJang/herd.git ~/herd
   ```
2. Install PyYAML if you do not have it: `sudo apt install python3-yaml`
3. Run the setup script:
   ```bash
   ~/herd/setup.sh
   ```
   It links these. It never overwrites a real file or folder. If it prints `SKIP`, move that file's contents into herd, remove the file, and run the script again.

   | Link | Target |
   |---|---|
   | `~/.claude/skills` | `herd/skills/` |
   | `~/.config/opencode/AGENTS.md` | `herd/AGENTS.md` |
   | `~/.claude/CLAUDE.md` | `herd/CLAUDE.md` |
   | `~/.config/opencode/agents/eye-*.md` | `herd/.opencode/agents/` |
   | `~/.config/opencode/commands/*.md` | `herd/.opencode/commands/` |

4. Point OpenCode to the herd safety rules. Add this line to `~/.bashrc` (or `~/.zshrc`), then open a new terminal:
   ```bash
   export OPENCODE_CONFIG="$HOME/herd/opencode/permissions.jsonc"
   ```
   Keep no `permission` block in `~/.config/opencode/opencode.json`.
5. Start OpenCode and ask: "Which skills can you see?" `eye` must be in the list.

Note: Do not also link `~/.agents/skills`. OpenCode reads both folders, so it would find each skill twice.

## Use

| Command | What it does |
|---|---|
| `/cassie <anything>` | **Main entry point.** Picks the playbook (feature, review, or a local work playbook) or skill for the request. |
| `/eye` | Review the current branch |
| `/eye <pr-url or number>` | Review a GitHub PR. For other people's PRs, it writes draft comments to `~/branches/.herd/drafts/`. It never posts. |
| `/eye --standard --level senior` | Force a tier and a teaching level |
| `/learn` | Show my concepts: learning and known |
| `/quiz` | Answer pending Learn questions |
| `/how <question>` | How code works, at my level |
| `/why <question>` | Why code is this way, from commits, PRs and tickets |
| `/teach <topic>` | How and why together, as one explanation |
| `/blast-radius <change>` | What a change can break in other repos |
| `/interrogate` | Adversarial review: findings proven by running code (slower) |
| `/arena <task>` | Parallel candidates, best one merged (expensive) |
| `/grill-me` | Stress-test a plan |

From a terminal: `opencode run "/eye 123"`.

**Without AI:** run a shortcut from `herd/bin` in any terminal, or with `!` in OpenCode (for example `!herd-usage`). Run `herd-help` to list them.

## Configuration (`herd.yaml`)

| Key | What it does |
|---|---|
| `me.github` | My GitHub login. eye uses it to tell my PRs from other people's PRs. |
| `models.triage` | Fast model: diff summary, risk label, tier |
| `models.code` | Model that writes code |
| `models.reviewer` | Single reviewer in the quick tier |
| `models.judgment` | Lead reviewer: teaching and the final report |
| `models.panel` | Reviewers from different model families, for standard and deep tiers. Also the arena and interrogate runners. |
| `models.judge` | Cross-judge for arena and trail reviewer for show-me-your-work. Use a different family from your session model. |
| `review.quick_max_lines` | Diffs smaller than this can be quick tier |
| `review.standard_max_lines` | Diffs up to this size are standard tier |
| `review.deep_paths` | A diff that touches these paths is deep tier |
| `review.max_findings` | Findings in the report, most important first |
| `review.tiers` | Which roles run in each tier |
| `teaching.default_level` | `eli5`, `junior` or `senior`, for concepts that are not in memory.md |
| `teaching.learn_concepts_max` | Concepts in each Learn section |
| `coding.default_mode` | `driver` (agent writes) or `navigator` (I write) |
| `budget.log` | Path of the usage log |
| `budget.downgrade_when_over` | Lower the tier when a review is over budget, and say so |
| `budget.max_tokens_per_review` | Token limit per review. `null` = no limit yet |
| `paths.*` | Work folders for tasks and drafts |

After you change `models` or `review.tiers`, run `~/herd/scripts/gen-agents.sh`.

Model IDs must match the output of `opencode models github-copilot`.
